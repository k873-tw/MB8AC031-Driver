# GV-M2TV の選局（地上波）

選局の手順はライブラリの [`fe_m2tv.c`](../src/lib/fe_m2tv.c) に組み込んであり、テーブルファイルは使いません。
残している書き込みは、どれも GV-M2TV の実機（CFW）で外したりビットを変えたりして、効果を確認したものです。
それぞれ、外すと何が起きたかを下の表にまとめています。

## 接続

| デバイス | アドレス | アクセス方法 |
|---|---|---|
| 復調 IC | 7 bit `0x18` | `[reg 値]` を書く。読むときは `[reg]` を書いてから読む |
| チューナー | 復調 IC の先 | 復調 IC に `[FE C0 reg 値]` を書くと、チューナーの `reg` に届く。読むときは `[FE C0 FB reg]`、`[FE C1]` の順に書いてから読む |

復調 IC にはリセット方法が見つかっていません。そのため、下の表で「bit を〜に」としている書き込みは、
読み出してから該当ビットだけを変え、ほかのビットは機器の値のまま残します。

## 初期化（最初に 1 回）

| 書き込み | 確認した結果 |
|---|---|
| チューナー `0xFF`（データなし） | リセット。この後チューナーのレジスタを読むと、`0x00` と `0xD5`〜`0xD8`（勝手に変わる）以外は電源投入時の値に戻っている |
| 復調 `0x11`・`0x12`・`0x13` の bit2〜0 を 6・4・3 に | どれか 1 ビットでも電源投入時の値（1・3・4）に戻すとロックしない。上位 5 bit はそのまま |
| 復調 `0x14` の bit6 を 1 に | 0 だとロックしない。電源投入時は `0x0A`。bit3 と bit1 はどちらでもよい |
| 復調 `0x16` の bit1〜0 を 0 に | どちらかが 1 だとロックしない。電源投入時は `0x03` |
| 復調 `0x30` の bit3 を 0 に | 1 だとロックしない。電源投入時は `0x28`。bit5 はどちらでもよい |
| 復調 `0x31` の bit1 を 0 に | 1 だとロックしない。電源投入時は `0x0F` |
| 復調 `0x34` の bit5 を 0 に | bit5 と bit4 が両方 1（電源投入時の `0x3F`）だと、C/N が数 dB 落ちて TS にエラーが出る。弱いチャンネルはロックしない。片方だけ 1 なら問題ない |
| 復調 `0x1C` の bit6 を 0 に | 1（電源投入時の `0x55`）だと、ロックまで数秒かかって C/N が数 dB しか出ないか、ロックしない。ほかのビットはどちらでもよい |
| チューナー `0x02` = `0x02` | bit2 は 0 にする（1 だとロックしない）。電源投入時は `0x06`。bit1 はどちらでもよい |
| チューナー `0x01` = `0x01` | 0（電源投入時）だとロックしない |
| 復調 `0x1E` の bit4・bit2、`0x1F` の bit6・bit4 を 0 に | どれか 1 つでも 1 だと（電源投入時はどちらも `0x54`）、ロックしてデータも出るが TS にならない（PAT が無い）。ほかのビットはどちらでもよい |
| 復調 `0x75` の bit3 を 1 に | ヌルパケットの大部分を省く。0（電源投入時）だと、どのチャンネルも一定の速さで流れ、余りはヌルパケットで埋まる。番組のパケットは同じ（数が一致し、連続性カウンタの飛びも無い）。`0x76` の bit3 でも同じ結果になる。ロックや TS の正しさには関係ないが、USB の帯域と録画サイズを減らすために入れている |

## 選局ごと

| 書き込み | 確認した結果 |
|---|---|
| チューナー `0x0D`・`0x0E` | 周波数（1/64 MHz 単位）。`(kHz × 64 + 500) ÷ 1000` の下位・上位バイト（557,143 kHz → `0x8B49`） |
| チューナー `0x0F` = `0x01` | 新しい周波数を反映させる。抜くとロックしない。先に `0x00` を書かなくても、続けて選局（スキャン）したときに毎回チャンネルが変わる |
| 復調 `0x01` = `0x40` | 抜くと、あるチャンネルはロックせず、別のチャンネルはロックまで 2.3 秒かかる |

## 書かないもの

次のものは、書いても書かなくても、ロック、ロックまでの時間、C/N、TS のエラー（同期、連続性、TEI、PAT）が変わりませんでした。

- 復調 `0x23`（電源投入時の値のままでよい）
- チューナー `0x80`（UHF では `0x01` でも `0x41` でも同じ）

TS のビットレートについては、復調 `0x1D`・`0x75`・`0x76`・`0x77`・`0x7D`・`0xEF` を試し、
効いたのは `0x75` と `0x76` だけでした（上の表）。

## ロック判定と C/N

- ロック: 復調 `0x80` の bit5 と bit3 がどちらも 0、`0xB0` の下位 4 bit が 8 以上、
  `0x96` の bit7〜5 のどれかが 1。ロック前は `0x80` = `0xAF`、`0xB0` = `0xA0`、`0x96` = `0x00`
- `0x96` を見ないと判定が早すぎます。`0x80` と `0xB0` だけを 20 ms ごとに見た場合、
  TS の最初の約 0.5 秒に、訂正できなかったパケット（TEI）が 1,100〜1,300 個と、連続性カウンタの飛びが出ました
- C/N: 復調 `0x8B`〜`0x8D` の 24 bit。小さいほど良い。dB への換算式はまだありません

## 対応範囲

- 470〜700 MHz（UHF 13〜50 ch）のみ。700 MHz 以上は、受信できるチャンネルが無かったため測っていません
- CATV（パススルー）も測っていません。332 MHz 未満ではチューナー `0x80` の切り替えが必要かもしれませんが、未確認です。ドライバは受け付けません

## 確認したチャンネル

受信できる UHF のチャンネルはすべてロックしました。
録画で確認したのは、ロックする中で最も弱いチャンネルと、もう 1 チャンネルです。
電源を入れ直した直後からこのライブラリだけで選局して、同期の取り直し・連続性カウンタの飛び・TEI がいずれも 0、PAT もありました。
