## 枠のやりとり

ホストは 64 バイトの `FRQ1` の枠を機器の郵便受けに書き込み、呼び鈴を鳴らして、
同じ場所から応答を読みます（CFW の `docs/frq1.md`）。応答かどうかは、マジック、
コマンドのエコー、連番、状態が 0 以外になったこと、の 4 点で判断します。

郵便受けは 4 つあり、用途ごとに分けています。

| 番号 | 用途 |
|---|---|
| 0 `MB8_BOX_MAIN` | 録画、管理ツール、BonDriver |
| 1 `MB8_BOX_CARD` | IFD ハンドラ |
| 2 | CFW の ARM 用ツール |
| 3 | 未使用 |

同じ郵便受けを 2 つのプログラムが使うと、お互いの枠を上書きしてしまいます。
分けておけば録画しながらカードを使えます（GV-M2TV と PIX-DT295 の実機で、CFW のサンプルを使って確認済み）。
同じプロセスの中では、ハンドルごとの mutex で 1 枠ずつ送ります。

枠を送る前に hook を読みます。CFW の stub（`ldi:20 #entry,r12 ; jmp @r12 ; nop`）が無ければ、
郵便受けの番地は純正ローダが使っている場所なので、何も書き込みません。

## TS の受信

CFW にはメインループがありません。`STREAM` の 1 枠は「今出せる分を出して戻る」だけです。
そのため、枠を送るスレッド（pump）と、バルク IN を読み続けるスレッド（reader）を分けています。

- dione（GV-M2TV）: 1 枠で既定 64 ブロック（32 KiB）を転送し、ブロックごとにエンドポイントの FIFO が空くのを待つ。
  読み手がいないと枠が終わらない
- selene（PIX-DT295）: 先に `START` を送る。1 枠は最大 64 バースト。エンドポイントが詰まると早めに戻るので、
  こちらも読み手が必要

reader は、ストリームがパケットの途中から始まることを前提にしています。`0x47` と、その 188 バイト先の `0x47` で
先頭を探し、そろったパケットだけをリングバッファに積みます。同期が外れたら探し直し、回数を数えます。
バッファが一杯のときは新しいパケットを捨てて数えます（古いものは消しません）。

停止するときは pump を止めて `STOP` を送り、エンドポイントに残っている分を取るために 250 ms 待ってから reader を止めます。

ストリームを流したまま選局し直せます。選局の I2C も同じ mutex を通るので、pump の枠と交互に送られます。
BonDriver は選局し直した後にリングバッファを捨てます。

## CFW のロード

機器は挿すたびに純正ローダの状態で起動します。CFW は RAM に置くので、毎回ロードし直します。
`mb8_ensure_firmware()` は hook を読み、CFW が動いていなければロードします。

手順は CFW の `frc1_load` と同じ 5 段階です（理由は `install.c` の先頭に書いてあります）。

二重にロードしないための仕組みは 3 つあります。

- `mb8_ensure_firmware()` は、hook に CFW の stub があれば何もしません（ビルドは比べません）
- `mb8_install()` は、hook とコードのセグメントを読み比べ、同じビルドが入っていれば何も書きません（`--force` のときを除く）
- 最初に書き込む直前に、インターフェース 0 を取ります。インターフェースの取得はプロセスをまたいで排他なので、
  別のプロセスがロード中か録画中なら、取れるまで最大 30 秒待ちます。取れたらもう一度読み比べ、
  待っている間に同じビルドが入っていれば何も書きません。30 秒たっても取れなければ、何も書かずに `MB8_E_BUSY` を返します

取ったインターフェースは、ロードの後も閉じるまで放しません。放すと、ロードしたプロセスが録画を始めるまでの間に
別のプロセスが割り込めてしまうためです。カードだけを使う IFD ハンドラはロードをしないので、インターフェースを取りません。
同じプロセスの中では `call_lock` で直列にしており、そのハンドルで録画中ならロードを断ります。
純正の hook の 8 バイトはコンテナには入っておらず、指紋だけが入っています。
ロード時にチップから読み出し、`<コンテナ>.hook` に保存します。

## カード

T=1 のプロトコルはすべてホスト側で処理します。CFW はカードの信号線とバイトの送受信だけを担当します。
ATR から F、D、CWI、BWI を決めて `CARD_PARAM` を送り、S(IFS 251) を 1 往復させます。
PPS は行いません。T=1 のエラー検出は LRC のみです。

IFD ハンドラは、呼ばれたときだけ USB を開きます。録画が同じ機器を使うためです。
T=1 の状態は呼び出しをまたいで保持し、開き直した機器に付け替えます（`mb8_card_rebind`）。

抜き差しの扱い: GV-M2TV のカードは抜けない構造なので、一度検出したら以後は問い合わせません。
PIX-DT295 は抜けるので 500 ms ごとに問い合わせます。

## エラーコード

`MB8_E_NOTIMPL`〜`MB8_E_BUSY`（-1〜-7）は CFW の `FW_*` と同じ値です。
それより小さい値はホスト側のエラーです（USB のエラー、応答が無い、CFW が動いていない、機種が未対応、など）。
メッセージは `mb8_error()` で取得できます。
